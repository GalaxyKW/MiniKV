# MiniKV 使用与配置

[返回 README](../README.md) · [存储与协议设计](design.md) · [运行状态](observability.md) · [测试与压测](testing.md)

本文中的命令均在仓库根目录执行。引擎和 HTTP 网关是两个独立进程；环境变量分别传给对应进程。

## 构建与启动

构建需要 Linux、支持 C++17 的编译器、CMake 3.16+、Make 和 Go 1.22+。引擎依赖 Linux 的 `epoll`、`eventfd` 和 `flock`。Go 程序没有第三方模块依赖；Python 3 用于端到端测试，Matplotlib 仅在绘图时需要。

```sh
make JOBS=4
```

默认构建类型为 `RelWithDebInfo`；不指定 `JOBS` 时使用 2 个并行任务。

| 产物 | 用途 |
| --- | --- |
| `build/engine` | C++ 存储引擎与 TCP 服务 |
| `bin/minikv-go` | Go HTTP 网关 |
| `bin/minikv-bench` | HTTP 压测工具 |

终端一启动引擎：

```sh
MINIKV_DATA_DIR=./data \
MINIKV_WAL_MODE=reliable \
MINIKV_WAL_FLUSH_MS=2 \
./build/engine
```

终端二启动网关：

```sh
MINIKV_HTTP_ADDR=127.0.0.1:8080 ./bin/minikv-go
```

示例显式选择可靠模式和 2 ms 刷新触发间隔；程序默认是 `throughput` 和 100 ms。引擎默认监听 `127.0.0.1:9090`。网关默认监听 `:8080`，即所有接口；示例将其限制为本机地址。当前服务没有内置鉴权或 TLS。

`MINIKV_DATA_DIR` 相对于**启动进程的工作目录**解析，与可执行文件的位置无关。换一个目录启动并继续使用 `./data`，会指向另一个数据库；跨目录使用时建议配置绝对路径。网关不直接读取数据文件。

## HTTP API

数据操作使用 `/kv`。存储层的 PUT 对应 **HTTP POST**，用于新建或覆盖值。

| 操作 | 方法与参数 | 成功响应 |
| --- | --- | --- |
| 写入 | `POST /kv`，JSON 对象含 `key`、`value` | `200`，`OK\n` |
| 读取 | `GET /kv?key=...` | `200`，`VALUE ` + 原值 + `\n` |
| 删除 | `DELETE /kv?key=...` | `200`，`OK\n` |

```sh
curl -sS -i -X POST http://127.0.0.1:8080/kv \
  -H 'Content-Type: application/json' \
  -d '{"key":"tenant:1","value":"hello\nworld  "}'

curl -sS -i --get http://127.0.0.1:8080/kv \
  --data-urlencode 'key=tenant:1'

curl -sS -i -X DELETE 'http://127.0.0.1:8080/kv?key=tenant%3A1'
```

key 必须为 1–4096 字节，value 为 0–1048576 字节（1 MiB）。限制针对解码后的字节长度，中文等多字节字符按 UTF-8 字节数计算。value 可为空字符串，省略时也写入空字符串。GET/DELETE 的 key 使用 URL 编码。

POST 只接受一个 JSON 值；未知字段、尾随另一个 JSON 值及格式错误会返回 400。请求体另有 `6 × (4096 + 1048576) + 1024` 字节的上限，为 JSON 转义预留空间；解码后的 key/value 仍受上述限制。

HTTP 输入使用 JSON 字符串，可以表示 Unicode、换行、冒号、NUL（`\u0000`）和尾部空白。底层二进制 RPC 支持原始字节；HTTP JSON 不提供无效 UTF-8 字节的无损往返保证。

| 结果 | HTTP 状态 | 响应 |
| --- | ---: | --- |
| 写入或删除成功 | 200 | `OK\n` |
| 读取命中 | 200 | `VALUE ` + 原值 + 一个换行 |
| 读取或删除未命中 | 404 | `NOT_FOUND\n` |
| key、JSON 或后端参数无效 | 400 | 文本错误说明 |
| 不支持的方法，包括 HTTP PUT | 405 | 文本错误说明；`Allow: POST, GET, DELETE` |
| value 或请求体过大 | 413 | 文本错误说明 |
| 后端通信失败或响应无效 | 502 | 文本错误说明 |
| 存储 I/O 失败、请求容量已满或 RPC 客户端已关闭 | 503 | 文本错误说明 |
| RPC 请求预算耗尽 | 504 | 文本错误说明 |

响应使用文本格式。读取 value 时，只移除固定的 `VALUE ` 前缀和最后一个换行，不能对整个响应做 trim；空 value 的响应为 `VALUE \n`。

网络失败、超时或客户端取消后，写入可能已经执行。网关不自动重试写入和删除；GET 最多在原超时预算内重试一次。RPC 超时覆盖连接池等待、拨号和收发，开始于 HTTP 参数解析之后。取消网关等待不会撤销已经提交给引擎的操作。

## 配置参考

只读的 `GET /stats` 返回引擎与网关运行状态，格式与 `/kv` 的文本响应不同；完整 JSON 字段、计数口径及故障响应见[运行状态指南](observability.md)。

### 引擎：数据与持久化

| 环境变量 | 默认值 | 含义与范围 |
| --- | --- | --- |
| `MINIKV_DATA_DIR` | `./data` | 相对工作目录或绝对数据目录 |
| `MINIKV_WAL_MODE` | `throughput` | `throughput` / `reliable` |
| `MINIKV_WAL_BATCH_SIZE` | `512` | 触发批量同步的排队记录数；1–65536 |
| `MINIKV_WAL_FLUSH_MS` | `100` | 同步触发间隔，毫秒；1–60000 |
| `MINIKV_WAL_QUEUE_BYTES` | `16777216`（16 MiB） | 未同步 WAL 字节上限；2097152–1073741824 |
| `MINIKV_SNAPSHOT_INTERVAL_MS` | `1200000`（20 分钟） | 自动快照间隔，毫秒；0–86400000，0 禁用 |

`throughput` 在内存更新、WAL 入队后返回；未同步写入可能在故障中丢失。`reliable` 等到 WAL 完成 `fdatasync` 后确认；GET 也等待其观察到的状态持久化。刷新间隔是触发条件，不能据此承诺固定的最大数据丢失时间窗口。

WAL 队列额度包含正在写盘但尚未同步的批次，容量不足时写请求等待。它不限制内存数据集大小。禁用自动快照后，WAL 会持续增长；当前没有内存淘汰策略或磁盘容量上限。快照的锁、额外内存和 WAL 后缀重写开销见[设计说明](design.md#wal-io-与状态锁)。

### 引擎：网络与请求调度

| 环境变量 | 默认值 | 含义与范围 |
| --- | --- | --- |
| `MINIKV_ENGINE_HOST` | `127.0.0.1` | IPv4 监听地址，不能使用主机名 |
| `MINIKV_ENGINE_PORT` | `9090` | TCP 监听端口；1–65535 |
| `MINIKV_WORKERS` | `20` | 执行数据操作的 worker 数，不含 WAL、快照、可靠完成和 Stats 线程；1–1024 |
| `MINIKV_REQUEST_QUEUE_SIZE` | `128` | 等待执行的请求上限，不含正在执行的任务；1–65536 |
| `MINIKV_MAX_CONNECTIONS` | `256` | 引擎连接总数上限；1–65536 |
| `MINIKV_CLIENT_IDLE_MS` | `30000` | 连接无进展超时，毫秒；1–3600000 |

数据请求的整个处理过程还有 `MINIKV_WORKERS + MINIKV_REQUEST_QUEUE_SIZE` 个名额，默认 148，覆盖排队、执行、可靠确认和等待 reactor 处理结果。可靠确认交给独立完成线程，释放数据 worker；WAL 字节容量不足仍会阻塞 worker。请求名额或工作队列满时返回 BUSY，由网关映射为 503。断连不撤销操作，也不提前释放仍在等待确认的请求名额。

连接数达到上限时，引擎关闭新连接。一条 TCP 连接最多执行一个请求，空闲或尚未接收完整帧的连接不占工作线程。请求名额释放后，尚未发送完的响应仍受连接数量与帧大小限制。

Stats 使用额外的固定 1 个工作线程、1 个待执行位置和 2 个整请求名额，数据任务容量不包含它们；状态连接仍计入 `MINIKV_MAX_CONNECTIONS`。

### 网关

| 环境变量 | 默认值 | 含义与范围 |
| --- | --- | --- |
| `MINIKV_ENGINE_ADDR` | `127.0.0.1:9090` | 连接的引擎地址，`host:port` |
| `MINIKV_HTTP_ADDR` | `:8080` | HTTP 监听地址 |
| `MINIKV_RPC_POOL_SIZE` | `64` | 数据 RPC 池到引擎的空闲与活动连接总上限；1–65536 |
| `MINIKV_RPC_TIMEOUT_MS` | `2000` | 单次操作的 RPC 总预算，毫秒；1–60000 |

更改引擎监听地址后，应同步设置网关的 `MINIKV_ENGINE_ADDR`。增加连接池容量不会增加引擎工作线程或 WAL 队列额度。

状态查询有独立的容量为 1 的 RPC 池，沿用同一个引擎地址和 RPC 超时，因此网关到引擎的总连接数最多为 `MINIKV_RPC_POOL_SIZE + 1`。

网关还有固定的 500 ms 拨号超时、15 秒 RPC 连接空闲复用期限。HTTP 读头超时为 5 秒、读取整个请求超时为 15 秒、写响应超时为 RPC 配置值加 5 秒、空闲连接超时为 30 秒，最大请求头为 64 KiB。这些值目前没有对应环境变量。

## 停机、备份与恢复

先在网关终端按 Ctrl+C，待其退出，再在引擎终端按 Ctrl+C；发送 SIGTERM 的顺序相同。网关提供 5 秒 HTTP 停机宽限期。引擎停止接收新连接和请求，给已接纳请求最多 5 秒发送响应，再等待存储任务完成并同步剩余 WAL。磁盘 I/O 阻塞可能延长引擎退出时间；5 秒不是整个存储关闭过程的上限。

正常关闭会排空 WAL，不要求生成新快照。备份前应停止服务并确认正常退出，然后复制整个数据目录。恢复时使用同一次备份中的 `snapshot.v1` 与 `wal.v1`，在单独目录验证恢复结果后再使用；运行时分别复制这两个文件不能保证得到一致备份。

| 现象 | 行为与处理 |
| --- | --- |
| 数据目录正在使用 | `LOCK` 的文件锁阻止第二个引擎打开；检查已有进程，不要通过删除锁文件绕过 |
| `wal.v1` 存在但快照缺失，即使 WAL 为空 | 拒绝启动，避免误建空库；保留目录，检查备份 |
| 快照存在但 `wal.v1` 缺失 | 拒绝启动，不会补建空 WAL |
| 完整记录校验错误、日志序列缺失或快照损坏 | 拒绝启动；保留原文件，检查存储问题并从完整备份恢复 |
| WAL 最后一条记录不完整 | 恢复时可截断不完整尾部，再继续启动 |
| 运行时 WAL 写入、同步或替换失败 | 引擎记录错误并拒绝后续请求；先检查磁盘、权限及日志，再验证恢复 |

没有在线备份或 HTTP 手动快照接口。出现恢复错误时，不要先删除 WAL、快照或清空数据目录；只有明确不再需要原数据时，才选择一个新目录初始化。恢复规则与故障边界见[文件格式与恢复](design.md#wal-和快照文件)。

## 旧版数据迁移

旧版文本 TCP 协议与当前二进制协议不兼容，引擎和网关需要一起升级。HTTP 写入成功响应保留原格式，GET/DELETE 未命中使用 404。

停止旧进程并备份整个旧数据目录后，执行：

```sh
MINIKV_DATA_DIR=./data ./build/engine --import-legacy
```

导入读取旧 `data.db` / `wal.log`，生成 `snapshot.v1` / `wal.v1`，保留原文件。**命令导入完成后退出**；随后按本文的启动命令分别运行引擎与网关。已有 v1 快照时拒绝再次导入。

旧引擎没有新版目录锁，必须先停止。旧格式无法无歧义表示的内容，以及旧版已经丢失或损坏的数据，不能通过迁移自动还原。完整约定见[旧版数据迁移](design.md#旧版数据迁移)。
