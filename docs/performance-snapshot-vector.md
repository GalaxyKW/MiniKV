# 隔离原型：连续数组快照副本的收益与采用门槛

[返回 README](../README.md) · [已有共享值原型](performance-snapshot-shared-values.md) · [实验工具](benchmark-experiments.md)

本次尝试将快照副本从 `unordered_map<string, string>` 改为 `vector<pair<string, string>>`：写盘只需顺序遍历，副本无需哈希索引。在线 KV、PUT/GET 路径及字符串表示不变；仍在同一状态锁内深复制全部 key/value，完整复制成功后才脱离待提交 WAL。改动不消除与数据量成正比的复制成本，也要求一块连续的 pair 存储空间。

**原型未通过本批预先声明的采用门槛，未并入主分支。** 16 轮全部正常完成。主场景第一对 OFF 的成功 QPS 比值为约 0.853、P99 比值约 1.331；ON 的 P99 比值约 2.144，均有门槛越界。失败判断只表示本批证据不足以采用，不证明这些差异由代码导致。其他配对和全部慢轮同样保留。

## 采用规则

规则在首轮前冻结，使用未四舍五入的原始数据。全部条件都满足才可采用：

- 16 轮均通过实验校验，测量至少 20 秒；每个 ON 的共同内部 idle 窗口至少完成 3 次快照，且无失败。
- 四个 ON 配对的捕获持锁均值 B/A 都不超过 0.90。
- 八个客户端配对的 QPS B/A 至少 0.95，P99 不超过 1.10，P99.9 不超过 1.20，max 不超过 1.50。
- 八个 Engine 测量区间采样 RSS 最大值配对均不超过 1.10；缺失不补零，不用生命周期 HWM 替代。
- 冻结来源、执行副本及实验后存储检查全部通过；缺失或覆盖不足不能算通过。

这是保守工程筛选，不是统计显著性检验。尤其 max 对短时噪声敏感，越界不自动证明代码导致回退；也不能在看到结果后放宽阈值或删除异常轮。

## 证据边界

本次仅覆盖 throughput、闭环、固定长度 value 和均匀 key 访问。它不验证 reliable 或固定到达率下的收益；闭环分位数仅描述已发出的请求，不代表暂停期间未发出的需求。离散 RSS 采样可能漏掉瞬时峰值，HWM 是已观察的进程生命周期高水位，不能当成测量窗口真实峰值。

快照副本仍深复制全部字符串；数组只减少副本容器开销，没有消除捕获暂停。格式兼容不表示快照记录顺序或文件字节必须一致。功能回归通过与局部计量改善均不能代替端到端采用门槛。

## 存储核验、归档与复现

采样全部结束后，冻结 A/B 分别检查全部 16 个数据库，共 32 次 `--check`，均退出 0、`valid`、尾部字节为 0。P 的最终序列为 300,791、数据量 102,988,890 B；S 为 900,098、13,388,890 B；各库均为 100,000 key，与预置及实际 PUT 计数、settled 状态一致。完整 CRC/序列扫描不能代替对每个并发操作返回值的历史验证。
